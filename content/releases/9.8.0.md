## New CLI MCP server

**Mockoon CLI now includes a new `mcp` command** that starts a [Model Context Protocol (MCP)](https://modelcontextprotocol.io/) server and exposes your local mocks to AI assistants like Claude, GitHub Copilot, or Cursor.

Running `mockoon-cli mcp` prints a ready-to-use MCP client configuration snippet, and the server provides tools to list local mocks, start a mock, stop a running mock, and list currently running mocks in the session.

By default, mock files are discovered from the desktop application storage directory, and you can include additional directories with the `MOCKOON_DATA_DIRS` environment variable (semicolon-separated paths).

```json
{
  "servers": {
    "mockoon": {
      "command": "mockoon-cli",
      "args": ["mcp"],
      "env": {
        "MOCKOON_DATA_DIRS": "/path/to/dir1;/path/to/dir2"
      }
    }
  }
}
```

Learn more about the MCP server in the [CLI documentation](https://github.com/mockoon/mockoon/tree/main/packages/cli#mcp-command).

(Issue [#2150](https://github.com/mockoon/mockoon/issues/2150))

## Body size limitation

This release improves request payload protection across the server stack by introducing a dedicated `maxRequestBodySize` setting and enforcing it consistently. You can now configure the limit from the CLI with the [`--max-request-body-size` flag](https://github.com/mockoon/mockoon/tree/main/packages/cli#start-command), using either raw bytes or human-readable values like "10MB".

The default body size limit is set to 100MB (not configurable in the desktop application yet), and any request exceeding this limit will receive a `413 Payload Too Large` response.

> 🔒 This update was part of a [vulnerability disclosure (GHSA-845j-g722-g66h)](https://github.com/mockoon/mockoon/security/advisories/GHSA-845j-g722-g66h). We recommend to update to this version as soon as possible especially if you are exposing your mocks publicly, or to untrusted networks.

(PR [#2290](https://github.com/mockoon/mockoon/pull/2290))

## Responses list improvement

The **default response flag** indicator is now displayed next to the active response in the responses list. This makes it easier to identify the status of the active response without opening the menu:

![Response flag indicator in the responses list](/images/releases/9.8.0/responses-list-flag-indicator.png)

Note: this indicator is non-interactive and is only a visual indicator of the active response status. You can still change the response status by opening the response menu.

(Issue [#1792](https://github.com/mockoon/mockoon/issues/1792))

## Fixes

- Fixed a body parsing issue causing 404 errors when using the serverless package on AWS Lambda. (Issues [#2080](https://github.com/mockoon/mockoon/issues/2080) and [#2033](https://github.com/mockoon/mockoon/issues/2033))

## Chores

- We **updated the libraries and application dependencies** to their latest versions to fix several vulnerabilities and reduce the number of dependencies we use. (PR [#2288](https://github.com/mockoon/mockoon/pull/2288))
- We started migration to Angular signal forms by converting the existing custom form components to signal-based components. (PR [#2289](https://github.com/mockoon/mockoon/pull/2289))
